# Product requirements

Start with the problem, evidence, and affected users. State the hypothesis and expected outcome. Explain why the proposed approach fits, and compare to current behavior when useful.

Cover scope/non-goals, design/architecture, dependencies, validated constraints, risks, open questions, and success criteria. Separate prototype proof from production outcomes. Record a path for deliberately deferred work.

Use diagrams or comparison tables when they clarify. Cite evidence, label assumptions, and leave missing metrics explicit. Scale length to the decision and implementation needs, not an arbitrary template size.
