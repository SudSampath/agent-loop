# Draft or review a PRD

Read the [product requirements pattern](references/pattern.md) and relevant project evidence. Identify the intended audience from the request or project context. Use provided profile and writing guidance when available; a personal vault is optional.

If a relevant knowledge vault is configured, resolve it from the active instructions and read its INDEX.md before specific profile, voice, or audience notes. Do not invent a user's role or preferences when that context is absent.

Separate observed facts, assumptions, and missing metrics. Scale the artifact to the decision being made, and preserve the user's requested scope and output format. Produce the requested local PRD or review; publication is a separate authorized action.
